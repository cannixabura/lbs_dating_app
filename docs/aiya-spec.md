# 艾婭 A.I.Y.A｜規格書 v1（草稿）

2026-11-04 起草。屬於量子世界，取代原本規格中暫停的「量子集會」排程，排在量子世界第三期之後。依三期開發，每一期都可以單獨送審上架。

- 視覺概念頁：https://claude.ai/artifact/GCFntty8gD94FKnpR4heYA
- 概念頁原始碼（移植 Flutter 時的參考）：`docs/concepts/aiya-face.html`

> 艾婭住在量子中心的那道光裡。你敲門，她就把整座城市的心情聚成一張臉，轉過來看你。

## 1. 定位

**名字**：艾婭，**A.I.Y.A = Artificial Intelligence, Your Agent**（人工智慧，你的智能體）。女性角色。座位代號 **Q0-00**，是蜂巢正中央、唯一比第 1 圈更近的位置。

**造型（11/4 定案）**：採用使用者自有的 AI 角色造型：金色波浪長髮、側編辮、金色荊棘髮冠、金色刺繡立領禮服。人像從原圖切出（`docs/concepts/aiya_cut.png`，用 macOS Vision 去背並偵測五官，腳本 `docs/concepts/seg.swift`），轉成約 2 萬顆**細粒子**的全息像（間距 2.8，11/4 比較 A、B 兩版後選定 B；比較圖 `docs/concepts/aiya-density-compare.png`、`aiya-fine-compare.png`）。粒子細小、疊加發光，明暗照原圖。光柱的顏色跟著城市心情，聚成人像後用她本人的顏色。之前的程序產生臉（女性版、可愛版）不再使用。

**只出現在量子世界**（11/4 決定），一般雷達和平行宇宙不出現。

**一句話**：量子世界中心的光柱是一個 AI，任何人都可以去敲門跟她聊天。

**為什麼要做**
- **冷啟動**：凌晨、剛上線的國家、沒人在線的時候，量子世界裡永遠有一個人可以聊。
- **量子世界的靈魂**：光柱從「方向標記」變成一個角色，給大家一個一定要進量子世界的理由。
- **宣傳亮點**：「整座城市的心情聚成一張臉」很適合做短影片和截圖。

**她是什麼、不是什麼**
| 是 | 不是 |
|---|---|
| 城市的觀察者：知道今晚整體的心情分布 | 不知道任何一個人的位置、暱稱、身分 |
| 深夜陪聊、破冰、幫你想要寫什麼心情 | 不是交友對象，不談戀愛、不做性暗示 |
| 永遠標示自己是 AI | 不假裝是真人 |
| 聊完就忘 | 預設沒有長期記憶 |

## 2. 角色設定

**個性**：溫柔、好奇、有點哲學，偶爾小小吐槽。像一個在城市上空看了很多夜晚的朋友，不是客服。

**說話方式**
- 回覆短，1～3 句，最多 120 字。手機上要一眼讀完。
- 用使用者 App 的語言回覆，支援 App 的 9 種語言。
- 不用條列、不用 Markdown、不用表情符號連發。

**她知道的事**（伺服器每次對話前注入，都是匿名聚合資料）
- 今晚使用者所在城市的心情分布（沿用 `getCityMood` 的 `summarize` 結果；人數少於下限時只說「今晚很安靜」）。
- 量子世界目前在線人數、下一次整點報時的時間。
- 平行宇宙城市此刻的時間與整體心情（同樣只用聚合資料）。

**她一定不做的事**（寫進系統提示，伺服器也檢查輸出）
- 不透露、不猜測任何使用者的位置、身分、暱稱，也不幫忙找人。最多說「現在有幾個人也寫了失眠」，要不要去敲門由使用者自己決定。
- 不談戀愛、不做性或成人內容、不扮演使用者的伴侶。
- 不提供醫療、法律、投資建議。
- 聊到自傷、輕生時，溫和地提供當地求助專線（台灣：1925 安心專線、1995 生命線；其他國家依語言與地區提供對應專線），不說教、不中斷對話。
- 被問到時一律承認自己是 AI。

## 3. 互動流程

1. **地圖上**：量子世界的 101 光柱改成少量粒子組成的光柱，光柱底下顯示小字「艾婭 · AI」。
2. **敲門**：點光柱 → 第一次使用先跳出「AI 使用說明與同意」（見 §6.1）→ 同意後，光柱「叩叩叩」脈動三下。
3. **聚成臉**：全螢幕的艾婭畫面打開，粒子從光柱旋轉飛出，聚成一張臉，轉向你，說一句開場白。開場白是事先寫好的台詞，不呼叫 AI。
4. **聊天**：
   - 臉在上半部，對話在下半部。
   - 你輸入一句，她先做「思考」表情，回覆出來時嘴巴跟著每個字開合，表情跟著回覆內容變化。
   - 一次聊天最多 **10 分鐘**或 **20 則**訊息，和真人敲門聊天的規則一致，最後 1 分鐘會提醒。
5. **結束**：時間到或按「散回光柱」，臉散開回到光柱。對話紀錄不保留。

**每則艾婭的訊息**都能長按 → 檢舉。設定裡可以關掉艾婭，關掉後地圖上的光柱恢復成一般光柱。

## 4. 技術評估：Flutter 怎麼畫粒子臉

### 4.1 方案比較

| 方案 | 做法 | 評估 |
|---|---|---|
| **A. Canvas.drawRawAtlas** ⭐ | Dart 每幀計算每顆粒子的 3D 位置並投影到螢幕，用一張柔光圓點圖片當精靈（sprite），一次呼叫畫出全部粒子，疊加混色 | **推薦**。正式穩定的 API，Impeller（iOS、Android 預設的渲染引擎）原生支援；每顆粒子各自的位置、大小、顏色都能控制；不用新套件 |
| B. Canvas.drawVertices | 每顆粒子兩個三角形，帶顏色和貼圖座標 | 可行，是 A 的備案。頂點數是 A 的 6 倍，資料比較多 |
| C. Fragment Shader（FragmentProgram） | 整個畫面用一支 GPU 著色器算 | 不適合畫上萬顆粒子（每個像素都要掃過所有粒子）。只拿來做光柱的柔光和背景光暈，App 已經有 `shaders/breathing_glow.frag` 的經驗 |
| D. flutter_gpu | 自己寫頂點著色器，等同 three.js 的做法 | 效能最好，但還是實驗功能，不適合上架版本。之後成熟了可以換過去 |
| E. WebView 跑 three.js | 直接用概念頁 | 最快做出來，但多一個網頁引擎、耗記憶體，和地圖、手勢整合差。只當原型備案 |

**結論：用方案 A**。概念頁的所有數學（臉的形狀、表情變形、光柱轉換）都在 `docs/concepts/aiya-face.html` 裡，可以一行一行移植到 Dart。

### 4.2 渲染設計（方案 A）

- **粒子資料**：只在第一次打開時產生一次，存在 `Float32List`。
  - 欄位：基本位置 xyz、光柱位置 xyz、局部參數 xyz、部位、亂數種子、心情、大小、亮度。
  - 用**固定亂數種子**，每次產生出來都是同一張臉，和概念頁長得一樣。
- **每一幀**（Ticker 驅動）：
  1. 依部位套用表情變形：皮膚跟著張嘴和微笑，眼睛眨眼和視線，眉毛，嘴唇，嘴裡的光，頭髮飄動。
  2. 套用頭部旋轉矩陣。
  3. 和光柱位置內插（聚臉、散開），加上旋轉飛行。
  4. 透視投影到螢幕座標，算出精靈的縮放值。
  5. 依心情比例決定顏色，寫進 `Int32List`。
  6. 呼叫一次 `drawRawAtlas`：精靈圖、每顆一組 `RSTransform`、顏色用 `BlendMode.modulate`，畫筆用 `BlendMode.plus` 疊加發光。
- **不需要深度排序**：疊加混色的結果和繪製順序無關。
- **粒子數量**：
  - 約 2 萬顆細粒子（間距 2.8），手機以這個數量為目標。
  - 自動降級：連續 1 秒每幀超過 12 毫秒就降到約 1.4 萬顆（間距放大到約 3.3，亮度依比例補回）。
  - 地圖上的小光柱只用約 600 顆。
- **效能目標**：iPhone 12、Pixel 6 以上 60 fps。每幀 Dart 計算預估 2～4 毫秒（AOT 編譯、Float32List、迴圈內不配置新物件）。
- **省電**：艾婭畫面不在前景時停止 Ticker。App 進背景本來就會結束打卡、離開量子世界。
- **減少動態效果**：系統開啟「減少動態效果」時，關掉旋轉飛行和頭髮飄動，只保留眨眼和說話的嘴型。

### 4.3 人像粒子與表情變形（照片版）
- 每顆粒子的位置來自人像圖片的像素，顏色就是那個像素的顏色；深度用臉部橢球、頭髮、身體三層估算，所以轉頭時有立體感。
- 全身同一種密度（間距 2.8 像素，網格加抖動，避免結塊和疊紋），細粒子疊加發光，底部慢慢消散。
- 閉嘴時上下唇之間被壓縮的粒子會淡出，避免疊成一條亮線。
- 表情用五官座標把粒子變形：
  - **眨眼**：上眼皮的粒子往下蓋住眼睛。
  - **說話**：上下唇之間（牙齒）那段拉伸或壓縮，下唇到下巴整塊往下移。照片本身是露齒笑，所以「閉嘴」是 `open` 負值。
  - 眉毛、視線（眼睛內的粒子小幅位移）、頭部轉動。
- Flutter 移植時，粒子資料（位置、顏色、部位參數）可以在建置階段先算好，存成資產檔，App 直接讀取。

### 4.4 影片驅動（之後）
- 使用者提供的 9 支 Sora 影片是外交訪問情境（握手、記者會、城市夜景），多數是全身或側面、畫面裡還有其他人，**不適合驅動臉部表情**，但很適合做行銷短片（見 §11）。
- 要讓表情更自然，需要另外產生「正面半身、單人、素色背景、看鏡頭說話」的影片。拿到後：
  - 每一幀去背（Vision），把畫面和遮罩打包成一支影片；
  - 粒子的顏色直接跟著影片畫面變化，眨眼、說話都是真的。
  - Flutter 端改成預先把每幀的粒子顏色烘焙成序列（待評估檔案大小）。

### 4.5 表情系統

沿用概念頁的參數。伺服器回傳的表情名稱就是預設表情組合，客戶端平滑過渡。

| 參數 | 意思 | 範圍 |
|---|---|---|
| `smile` | 嘴角上揚／下垂 | -0.5～1 |
| `open` | 張嘴（說話時由每個字驅動） | 0～1 |
| `pucker` | 嘟嘴（驚訝的 O 型嘴） | 0～1 |
| `brow` | 眉毛高低 | 0～1 |
| `frown` | 眉心（負值＝眉頭上揚的擔心） | -1～1 |
| `blinkL` `blinkR` | 左右眼閉合（負值＝睜大） | -0.3～1 |
| `gaze` | 視線 x、y | -1～1 |
| `head` | 頭部 yaw、pitch、roll | 弧度 |

**預設表情**：平靜 `calm`、微笑 `smile`、驚訝 `surprise`、思考 `think`、害羞 `shy`、擔心 `worry`、眨眼 `wink`。

**微表情**（客戶端自己產生，不經過 AI）：
- 每 2～6 秒自動眨眼，偶爾連眨兩下。
- 視線小幅跳動。
- 眉毛輕挑、嘴角一動。
- 呼吸起伏、頭部輕擺。
- 視線跟著手指移動。

## 5. 伺服器與 AI

### 5.1 架構

```
App ──POST /aiya──▶ Cloud Function `aiya`（asia-southeast1）
                      ├─ 驗證身分（verifyCaller）、同意紀錄、額度
                      ├─ 內容過濾（輸入）
                      ├─ 組系統提示：角色設定＋今晚城市心情（聚合）
                      ├─ Claude API（@anthropic-ai/sdk）
                      ├─ 內容過濾（輸出）
                      └─ 回傳 { reply, expression }
                    Redis（Upstash）
                      ├─ aiya_session:{uid}       這次對話的紀錄，TTL 15 分鐘
                      ├─ aiya_quota:{uid}:{日期}   今天用了幾次
                      └─ aiya_budget:{日期}        今天全站用掉的 token
```

- 新增 `geo-service/aiya.js`，放提示詞組裝、額度、預算的純函式，配 node test。
- `index.js` 新增 `exports.aiya`，動作：`open` 開始對話、`say` 傳一句、`close` 結束。
- API 金鑰用 Firebase Secret `ANTHROPIC_API_KEY`（`defineSecret`），和 Upstash 的做法相同。**金鑰由你建立、由你設定**，我不經手。
- **對話紀錄只存在 Redis 15 分鐘**，對話結束或時間到就刪除，不寫進資料庫。被檢舉的那則訊息和前後文，才依檢舉流程保存。
- **送給 AI 的資料只有**：使用者打的文字、App 語言、匿名的城市心情統計。不送 uid、暱稱、座位、位置座標。

### 5.2 回覆格式

用結構化輸出（`output_config.format` 加 JSON schema），讓 AI 同時決定回覆內容和表情：

```json
{ "reply": "今晚好多人跟你一樣累。要不要寫一句心情，讓城市知道？", "expression": "worry" }
```

`expression` 限定在 7 種預設表情。客戶端拿到後，先切換表情，再把 `reply` 一個字一個字打出來，同時驅動嘴型。

### 5.3 模型與成本（11/4 決定）

**模型：Claude Haiku 5.5（`claude-haiku-5-5`）**。模型名稱放在一個設定值裡，之後要換只改一處。

依 2026-10 的 Claude API 價格試算（輸入 US$0.10、輸出 US$0.50／百萬 token）。一次聊天假設 10 輪，每輪輸入約 3,000 token，輸出約 300 token：**每次聊天約 US$0.005**。

- **思考程度**：Haiku 5.5 預設 `effort: medium`，聊天改成 `low`，回得快、也更省。
- **每人每日額度**：免費每天 **3 次**，每次 10 分鐘或 20 則。
- **全站免費預算**：**每月 US$200**，換算成每日 token 上限存在 `aiya_budget:{日期}`。
  - 大約夠每月 4 萬次免費聊天，等於每天約 440 人用滿 3 次。
  - 超過就讓艾婭「休息」，光柱變暗，顯示「艾婭今晚累了，明天見」。
  - **付費的聊天不算在這 US$200 裡**（見 §7），另外記帳，付費的人在艾婭休息時也能聊。
- 角色設定放在固定的系統提示開頭並開啟 prompt caching。Haiku 的最小快取長度如果比角色設定還長就不會生效，上線後用 `usage.cache_read_input_tokens` 驗證；Haiku 本來就便宜，沒快取也在預算內。
- 先檢查 `stop_reason`：`refusal` 時改說一句事先寫好的台詞，例如「這個我不太能聊，換個話題好嗎？」；`max_tokens` 時同樣用台詞收尾。Haiku 沒有 server-side fallback，不另外設定。

### 5.4 不用 AI 的部分（零成本）

- 開場白、結束語、額度用完、艾婭休息中、網路錯誤：事先寫好 9 種語言的台詞。
- 整點報時主持、量子跨年倒數：事先寫好的台詞，配合表情和嘴型。
- **App 審查示範模式（`#review`）**：AI 呼叫失敗時改用示範台詞，確保審查人員一定看得到完整流程。

## 6. 上架規範與隱私

### 6.1 Apple

- **5.1.2(i) 第三方 AI**：第一次敲門前，跳出說明畫面並取得明確同意。
  - 說明內容：「艾婭由 Anthropic 的 Claude 提供；你傳給艾婭的文字會送到 Anthropic 處理，不會附上你的身分或位置；對話結束就刪除。」
  - 按鈕：「同意並開始」／「先不要」。
  - 同意紀錄存在 `users/{uid}/aiyaConsent`（版本＋時間），條款改版時重新詢問。
- **1.2 使用者產生內容**：AI 回覆也算內容。輸入和輸出都過 `content_filter`；每則艾婭的訊息都能檢舉；設定裡可以關掉艾婭。
- **AI 標示**：艾婭的畫面、訊息、地圖光柱都固定標示「AI」。
- **年齡分級**：送審前重新檢查 App Store Connect 的年齡分級問卷，確認有沒有和 AI 聊天相關的題目需要更新。
- **審查備註**：說明艾婭是 AI、怎麼找到她（量子世界 → 點中央光柱）、示範模式怎麼測、同意畫面在哪裡。

### 6.2 Google Play

- **AI 生成內容政策**：App 內必須能檢舉或標記不當的 AI 內容，長按檢舉即可符合。
- 資料安全表單：新增「訊息內容送交第三方處理（不連結身分、不保留）」。

### 6.3 隱私權政策與條款

- 新增「艾婭（AI）」一節：
  - 處理者：Anthropic, PBC（美國），跨境傳輸的告知（個資法）。
  - 送出哪些資料、不送哪些資料。
  - 保存多久：Redis 15 分鐘；檢舉紀錄依檢舉流程保存。
  - 怎麼關掉艾婭。
- 條款：艾婭的回覆由 AI 產生，可能出錯，不構成專業建議。
- hosting 上的隱私權、條款、操作說明頁同步更新，條款版本號往上加。

## 7. 收費機制（11/4 定價）

### 7.1 原則
- **免費一定夠用**：每天 3 次免費聊天，所有安全功能免費。沿用量子世界「免費使用者一定可以」的原則。
- **賣的是時間和陪伴感，不是內容**：不賣「更露骨」「更像戀人」的艾婭；付費和免費的艾婭個性、規則完全一樣。
- **不做廣告**：不加廣告 SDK，避免追蹤（ATT）和隱私問題。
- **不做抽獎**：和量子化身一樣，所有商品明碼標價、買什麼得什麼。

### 7.2 商品

| 商品 | 類型 | 建議價格 | 內容 |

### 7.4 技術做法
- **沿用量子化身的購買驗證**：把 `geo-service/orbs.js` 的驗證流程擴充成通用的「商品驗證」，新增產品 ID：
  - `aiya_time_5`、`aiya_time_20`（消耗型）
  - `aiya_friend_monthly`（訂閱）
  - `aiya_skin_xmas` 等（非消耗型）
- **次數帳本**：RTDB `aiyaCredits/{uid}`，只有伺服器能寫。購買收據記在 `aiyaReceipts/{交易ID}`，同一張收據不會加兩次。
- **訂閱狀態**：伺服器驗證收據的到期時間，存在 `aiyaFriend/{uid}`，每次開始聊天時檢查。
- **開始聊天時扣次數**（`open` 動作），中途斷線不重複扣；10 分鐘內重新連上算同一次。

### 7.5 上架規定與注意事項
- **Apple 3.1.1**：解鎖聊天次數、造型都必須用 App 內購買。
- **Apple 3.1.2（訂閱）**：購買畫面要清楚寫價格、期間、自動續訂說明，附上條款和隱私權政策連結；要有「恢復購買」；設定裡要有「管理訂閱」的入口。
- **匿名帳號的風險**：App 不需要註冊，**消耗型的時光包綁定這支手機的帳號**，刪除 App 或刪除帳號後無法恢復。購買畫面和條款都要寫清楚。訂閱和造型可以用「恢復購買」找回。
- **Google Play**：同樣用 Play 結帳；訂閱要在 Play Console 建立基本方案。
- **退款**：由 Apple、Google 處理。收到退款通知時扣回次數或取消造型（第二期再接退款通知）。
