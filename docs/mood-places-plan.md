# 心情據點：開發規劃

2026-10-28 定案。第一階段只收大台北的獨立咖啡店（酒吧要改年齡分級問卷，之後再說）。

## 不變的原則

- 錢買不到能見度：不排名、不推播、不付費加權，名片上不放價格或招攬字句。
- 只在店門口 150 公尺內、營業時間內，雷達上才有那盞燈。
- 不追蹤：據點清單整份下載到手機，「是否在附近」只在手機上判斷。我們和店家都不知道誰經過了哪家店。
- 遵守手動打卡（App Store 5.1.2(i)）：只有 App 開著、已經打卡時才會看到燈和提示，背景不取得位置。

## 使用者看到的樣子

| 狀況 | 雷達上 |
| --- | --- |
| 離店超過 150 公尺，或不在營業時間 | 沒有燈 |
| 進入 150 公尺內 | 咖啡杯圖標浮現（只有圖標、沒有圓形外圈，免得像使用者氣泡），慢慢呼吸（約 4 秒一次，亮度 20%～80%，大小與光暈跟著漲落）；畫在氣泡上面 |
| 今天已經打開過這張名片 | 靜止的柔光（亮度約 45%、光暈小），不再呼吸，退到氣泡底下 |
| 系統開了「減少動態效果」 | 一律靜止 |
| 走出 150 公尺 | 燈淡出；再走回來重新浮現 |

**App 內提示**（不是系統推播）：第一次進入某家店 150 公尺內，上方浮出一張玻璃小卡「附近有一盞心情據點的燈 · {店名}」，點了打開名片，約 6 秒後自動消失。不響、不震動。

- 同一家店 7 天內只提示一次。
- 一天最多 2 次（所有店合計）。
- 設定裡有「心情據點提示」開關，預設開。關掉後燈還在，只是不提示。

**燈的位置**：雷達預設 2 公里，150 公尺只離中心約 40 像素，會壓在自己的頭像上。燈保留真實方向，預設比例下距離中心至少 72 像素（一圈「身邊的光」），雙指縮放時跟著等比例移動。

**據點名片**（點燈或點提示打開）：

- 從店裡往外看的夜景照片
- 店名、今天的營業時間（「營業到 22:00」）
- 一句心情故事，點一下用手機翻成使用者的語言，跟雷達氣泡一樣
- 地址（點了導航）、電話（點了撥號）
- 「導航」按鈕：打開手機的地圖 App，走路路線
- 小字「資料有誤？」：回報歇業、搬家、時間不對

## 資料與營運流程

不需要新的伺服器程式，全部放在網站（Firebase Hosting）：

```
places/places.json        ← 我們維護的原始資料（進 git）
places/photos/{id}.jpg    ← 店家提供的原圖
tool/build_places.py      ← 檢查欄位、轉照片、產生下面兩個檔案
hosting/places/v1.json    ← App 下載的清單
hosting/img/place/{id}.webp
```

新增或修改一家店：改 `places/places.json`、放照片 → 執行 `python3 tool/build_places.py` → 你部署網站。App 每次打開、之後每 6 小時重新下載一次（有快取，沒變就不重抓）。

每家店的欄位：

```json
{
  "id": "p001",
  "name": "某某咖啡",
  "lat": 25.04780, "lng": 121.51700,
  "address": "台北市中正區…",
  "phone": "02-2345-6789",
  "hours": { "mon": [], "tue": [["12:00", "22:00"]], "sat": [["12:00", "26:00"]] },
  "closed": ["2026-12-31"],
  "story": "下雨的晚上，窗邊那張桌子總是最先坐滿。",
  "partnerSince": "2026-11",
  "test": false
}
```

- 時間一律用台灣時間（UTC+8）計算，不管手機設在哪個時區。`26:00` 表示營業到隔天凌晨 2 點。
- `test: true` 的店只在開發版出現，用來在台北車站、淡水測試。
- 店家要下架時，從清單刪掉並部署，App 下次更新清單就消失。

## 開發分期

**第一階段：App 裡看得到（約 2～3 天）**

1. `places/places.json` 格式、`tool/build_places.py`（檢查欄位、轉照片、產生清單）、`firebase.json` 讓 `places/v1.json` 快取 10 分鐘
2. `lib/mood_place.dart`：下載與快取清單、營業時間判斷、150 公尺判斷、提示頻率紀錄
3. 雷達上的小燈：呼吸動畫、今天看過改成靜止、減少動態效果、最小半徑
4. 據點名片、翻譯、導航、撥號、回報有誤（寄信）
5. App 內提示與設定開關
6. 8 種語言的文字；操作說明加「10. 心情據點」（後面各節順延）；網頁版說明書重產
7. 隱私權政策中英文各加一列，說明清單下載到手機、不傳位置。不收新資料，所以不改條款版本，不用大家重新同意
8. 單元測試：營業時間（跨午夜、公休日、時區）、提示頻率；用模擬器和兩支手機在測試店實測

**第二階段：店裡的實體物**

- 每家店一個落地頁 `hosting/p/{id}.html`（名片預覽 + 下載 App，`?ref=place-{id}`）
- 桌卡 QR code、窗貼的印刷檔，從現有設計稿產生
- 只看匿名的 `ref` 安裝數，作為給店家的唯一回報

**第三階段：店內留言本**

- 只有在店裡（約 30 公尺內）才讀得到的低語，需要改伺服器的低語程式。第一、二階段穩定後再做。

## 第一階段進度（2026-10-28）

已完成：`lib/mood_place.dart`、雷達小燈與名片、App 內提示與設定開關、8 種語言、App 內操作說明第 10 節、`tool/build_places.py`、`firebase.json` 快取 10 分鐘、單元測試（`test/mood_place_test.dart`）。模擬器上台北車站、淡水兩家測試店都實測過。

- 呼吸中的小燈畫在氣泡**上面**（氣泡的點擊範圍很大，畫在下面會點不到），看過的柔光退到氣泡底下；進場鏡頭飛完才亮燈與提示。
- 開發時可以不部署，直接用本機的清單：`python3 -m http.server 8000`（在 hosting 資料夾）＋ `--dart-define=PLACES_URL=http://localhost:8000/places/v1.json`（只有模擬器連得到）。
- 網頁版操作說明（`hosting/guide.html`）與隱私權政策中英文的新增列，存在 `places/release-web.patch`，**App 上架這個功能時**才 `git apply places/release-web.patch` 並部署，避免網站先介紹還用不到的功能。

在 `mood-places` 分支開發，不影響 1.0.2 (9)。測好之後再決定併進哪一版，以及何時開始邀請店家（邀請信在 `marketing/outreach/mood-place-letter.md`）。

## 需要你提供或決定的事

- 照片：店家提供原圖。`build_places.py` 會統一調成夜景色調（壓暗、偏藍紫），不滿意的可以換成手修的版本。
- 心情故事：先只收中文一句（最多 40 字），其他語言用手機翻譯。
- 第一階段需要 1～2 家真實店家的資料來測試；在那之前先用 `test` 店。
